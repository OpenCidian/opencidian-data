## What it is

An open, community-corrected Chinese ↔ Vietnamese dictionary that AI models and apps can read. For each word: simplified and traditional forms, pinyin, the Hán Việt reading of each character, the Vietnamese meaning, the English definitions, the character breakdown, HSK level and frequency. Every value says where it came from.

- **Who it's for:** Vietnamese people learning Chinese, Chinese speakers learning Vietnamese (Hán Việt is the link between the two), and any model that would otherwise guess these answers.
- **The gap:** in a search on 2026-11-10 I found no public MCP or open API for Chinese→Vietnamese. The existing MCPs are Chinese-only (GraphChinese, kangxi-mcp, handict-mcp, zh-dict-mcp) or Hán-Nôm. The Vietnamese sites (hvdic.thivien.net, VDICT, Hanzii) have no API.
- **The name:** 词典 *cídiǎn* and 詞典 *từ điển* are the same word, read in Mandarin and in Hán Việt. GitHub user/org `opencidian` was free on 2026-11-10; `opencidian.com/.org/.dev` had no DNS records (not checked with a registrar). The listing title carries the keywords: "OpenCidian: open Chinese ↔ Vietnamese dictionary (Hán Việt, pinyin, character breakdown)".
- **By Perxel**, the same way as OpenRace: its own GitHub org (`opencidian`), with "by Perxel" in the READMEs and `/llms.txt`.

## The layers

```
opencidian-data (git: pinned sources + corrections + build)
   │  CI: build → validate → release dataset (versioned)
   ▼  POST /internal/sync (X-Sync-Secret), like openrace-data → openrace-api
opencidian-api ──▶ D1          the only thing that reads or writes D1
   ▲   ▲   └── GitHub issues   (suggestions from the app and the MCP land here, never in D1)
   │   └── hieu-chu-han server (REST, X-API-Secret; Vercel can't use a service binding)
   └── opencidian-mcp (service binding, X-MCP-Secret): the public face, /mcp, /llms.txt, /dash
```

- **The API is the only one that touches D1 and the GitHub token.** The public MCP holds neither: it passes a suggestion to the API, which opens the issue.
- **Same shape as OpenRace on purpose:** copy openrace-api's sync and lock middleware, and build the MCP from `perxel-mcp-kit`.

### The entry, with a source on every field

```jsonc
{
  "id": "觉|覺|jue2",             // simp|trad|pinyin-with-numbers: the same key CEDICT uses
  "simp": "觉", "trad": "覺",
  "pinyin": "jué", "pinyinNum": "jue2",
  "hanviet": [{ "char": "觉", "readings": ["giác"], "src": "unihan" }],   // one per character
  "vi":  { "text": "cảm thấy; tỉnh ngộ", "src": "cvdict" },
  "en":  { "senses": ["to feel", "to find that", "awake", "aware"], "src": "cc-cedict" },
  "hsk": { "level": 1, "src": "…" },
  "corrected": ["hanviet.0"]      // fields changed by a correction, if any
}
```

Characters get their own record: Hán Việt readings, radical, breakdown (meaning and sound parts, each with its own Hán Việt reading), stroke count.

**Problems in the current data that this fixes:**
- Hán Việt was read for the first character of a compound only (`getSinoVietnamese` in hieu-chu-han). Here every character gets its readings.
- Hán Việt is per character, not per pronunciation: 觉 *jiào* (a nap) and *jué* (to feel) both get "giác". A correction must be able to target one pronunciation.
- CVDICT text carries CEDICT markers into the Vietnamese ("LT:場|场[chang2]"). The build splits those into structured fields (measure words, see-also).
- kVietnamese covers only 8,300 characters; the 11 overrides in hieu-chu-han (父 phụ, 祖 tổ, 爱 ái, 说 thuyết, 睡 thụy, 旧 cựu, 雨 vũ, 闻 văn, 办 biện, 场 trường, 亮 lượng) were to be the first corrections. **Built:** with Thiều Chửu and traditional/variant fallbacks, 10 of them come from the sources; only 办 (biện before bạn) stays a correction.

### A correction

```yaml
# corrections/hanviet/说.yml
target: { char: "说" }            # or { entry: "觉|覺|jiao4" } for one pronunciation
field: hanviet.readings
set: ["thuyết", "thuế", "duyệt"]  # or add/remove
reason: kVietnamese has no reading for 说
evidence: Thiều Chửu, Hán Việt tự điển; hvdic.thivien.net/whv/说
by: phucbm
issue: 12                         # the issue it came from, if any
date: 2026-11-10
```

- The build applies sources first, then corrections. A source update that already contains the fix makes the correction a no-op: `validate` flags it so it can be removed.
- `validate` checks the schema, that each target exists, that values are well formed (tone marks, Vietnamese diacritics), and lists any correction that conflicts with another.
- Fixes to Vietnamese meanings that hold for everyone can also be sent upstream to CVDICT (it accepts issues and PRs).

### How a correction comes in

1. **Anyone opens an issue** with the "Correction" form: the word or character, the field, the current value, the suggested value, and the evidence. The same form is used by:
   - hieu-chu-han's report button (today it posts to Discord); the API opens the issue;
   - the MCP's `suggest_correction` tool, through the API, rate-limited, labelled `from-ai`.
2. **A maintainer turns it into a correction file** (by hand or with Claude Code), as a PR that says "closes #n".
3. **CI** builds and validates; on merge to `main` it publishes the dataset and calls the API's `/internal/sync`.

Suggestions never write to D1 and never commit. Issues are public: write it plainly in CONTRIBUTING that suggestions are public and credited.

## opencidian-api

Cloudflare Worker (Hono + zod, like openrace-api) over D1. Locked: every read route answers 404 without `X-MCP-Secret` (the MCP) or `X-API-Secret` (hieu-chu-han).

- `GET /v1/lookup?q=` — hanzi, pinyin (with or without tones) or Vietnamese → entries
- `GET /v1/entries/{id}`, `GET /v1/chars/{char}` — the full record
- `GET /v1/words-with/{char}` — compounds that contain a character
- `GET /v1/search?meaning=&lang=vi|en` — reverse lookup
- `POST /v1/annotate` — text → words, each with pinyin, Hán Việt and meaning
- `GET /v1/suggest?q=` — search as you type, for hieu-chu-han
- `POST /v1/corrections` — opens a GitHub issue in `opencidian-data` (rate-limited per caller)
- `POST /internal/sync` — `X-Sync-Secret`, loads a released dataset into D1
- `GET /v1/meta` — dataset version, build date, source versions, licence

**D1:** about 119K entries and about 10K characters, well within D1's limits. Full-text search: FTS5 over Vietnamese without diacritics, pinyin without tones, and English.

**Segmentation for `annotate`:** longest match against the dictionary (port `src/core/segmenter.ts`), with a test set of real lesson sentences from `ou-chinese-language`.

## opencidian-mcp

Built from `perxel-mcp-kit` (copy openrace-mcp's layout): `/mcp`, `/llms.txt`, `/dash`, public, no sign-in, rate-limited per caller.

| Tool | Answers |
|---|---|
| `lookup` | "What does 觉得 mean in Vietnamese?", "Which words are read *jue*?", "How do you say *cảm thấy* in Chinese?" |
| `get_character` | Hán Việt readings, radical, meaning and sound parts, strokes, HSK level |
| `words_with` | Common words that contain 觉 |
| `annotate_text` | A sentence split into words, each with pinyin, Hán Việt and meaning |
| `search_meaning` | Vietnamese or English → candidates in Chinese |
| `suggest_correction` | Opens a public issue; it never changes the data |
| `about` | Dataset version, sources, licence, how to cite |

Every answer carries `src` per field and the dataset version, so a model can cite it and a user can tell a source value from a correction.

Evals (`evals/questions.md`): Hán Việt for compounds, characters with more than one reading, Vietnamese → Chinese, a lesson sentence from OUC, a word that isn't in the dictionary (must say so, not guess).
